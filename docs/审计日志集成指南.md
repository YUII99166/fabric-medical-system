# 审计日志集成指南

## 概述

审计日志系统用于记录联盟中所有重要的业务操作，包括：
- 病历创建
- 补充记录添加
- 授权请求和批准
- 药品订单创建
- 保险报销申请
- 用户管理操作

日志同时写入MySQL数据库和区块链，读取时从MySQL查询以提高性能。

## 数据库更新

### 1. 执行SQL更新脚本

首先需要更新`audit_logs`表结构，添加组织信息字段：

```bash
# 进入MySQL容器
docker exec -it mysql bash

# 登录MySQL
mysql -u root -p123456

# 执行更新脚本
source /path/to/update_audit_logs.sql
```

或者直接在MySQL中执行：

```sql
USE fabric;

ALTER TABLE audit_logs 
ADD COLUMN organization VARCHAR(100) DEFAULT NULL COMMENT '所属组织MSPID' AFTER user_role,
ADD COLUMN organization_name VARCHAR(200) DEFAULT NULL COMMENT '组织名称' AFTER organization,
ADD COLUMN department VARCHAR(100) DEFAULT NULL COMMENT '科室' AFTER organization_name,
ADD COLUMN related_user_id VARCHAR(100) DEFAULT NULL COMMENT '关联用户ID（如患者ID）' AFTER resource_id,
ADD COLUMN related_user_name VARCHAR(255) DEFAULT NULL COMMENT '关联用户名（如患者姓名）' AFTER related_user_id;

CREATE INDEX idx_audit_organization ON audit_logs(organization);
CREATE INDEX idx_audit_org_name ON audit_logs(organization_name);
```

## 在API中集成审计日志

### 示例1：病历创建API

在`CreatePrescription` API中添加审计日志：

```go
func CreatePrescription(c *gin.Context) {
    appG := app.Gin{C: c}
    body := new(model.CreatePrescriptionBody)
    
    // ... 参数解析和验证 ...
    
    // 调用区块链创建病历
    resp, err := bc.ChannelExecute("createPrescription", bodyBytes)
    if err != nil {
        // 记录错误日志
        service.LogError(c, body.DoctorID, body.DoctorName, "doctor", 
            "create", "prescription", "", err.Error())
        appG.Response(http.StatusInternalServerError, "失败", err.Error())
        return
    }
    
    // 解析区块链响应
    var data map[string]interface{}
    json.Unmarshal(resp.Payload, &data)
    
    // 记录成功的审计日志
    prescriptionID := data["prescription_id"].(string)
    txID := resp.TransactionID
    
    err = service.LogPrescriptionCreation(
        c,
        body.DoctorID,           // 用户ID
        body.DoctorName,         // 用户名
        "doctor",                // 用户角色
        body.OrganizationID,     // 组织MSPID
        body.OrganizationName,   // 组织名称
        body.Department,         // 科室
        prescriptionID,          // 病历ID
        body.PatientID,          // 患者ID
        body.PatientName,        // 患者姓名
        txID,                    // 区块链交易ID
    )
    
    if err != nil {
        fmt.Printf("记录审计日志失败: %v\n", err)
        // 不影响主流程，只记录错误
    }
    
    appG.Response(http.StatusOK, "成功", data)
}
```

## 审计日志字段说明

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| user_id | string | 操作用户ID | "doctor123" |
| username | string | 操作用户名 | "张医生" |
| user_role | string | 用户角色 | "doctor" |
| organization | string | 组织MSPID | "TaobaoMSP" |
| organization_name | string | 组织名称 | "协和医院" |
| department | string | 科室 | "内科" |
| action | string | 操作动作 | "create", "update", "delete", "approve", "reject" |
| resource_type | string | 资源类型 | "prescription", "supplement", "access_request", "drug_order", "insurance_claim", "user" |
| resource_id | string | 资源ID | "prescription_001" |
| related_user_id | string | 关联用户ID | "patient123" |
| related_user_name | string | 关联用户名 | "李四" |
| description | string | 操作描述 | "医生 张医生 为患者 李四 创建了病历" |
| ip_address | string | IP地址 | "192.168.1.100" |
| user_agent | string | 用户代理 | "Mozilla/5.0..." |
| tx_id | string | 区块链交易ID | "abc123..." |
| status | string | 操作状态 | "success", "failed" |
| error_message | string | 错误信息 | "连接超时" |

## 资源类型定义

| 资源类型 | 说明 | 相关操作 |
|---------|------|---------|
| prescription | 病历 | create, update, view |
| supplement | 补充记录 | create, view |
| access_request | 授权请求 | request, approve, reject |
| drug_order | 药品订单 | create, update, complete, cancel |
| insurance_claim | 保险报销 | create, approve, reject |
| user | 用户 | create, update, delete, restore |

## 查询审计日志

### 通过API查询

前端可以通过以下API查询审计日志：

```javascript
// 获取活动列表
const response = await getAllianceActivities({
  page: 1,
  pageSize: 20,
  organization: 'TaobaoMSP',  // 可选
  activityType: 'prescription', // 可选
  startDate: '2026-01-01',     // 可选
  endDate: '2026-12-31'        // 可选
})

// 获取统计数据
const stats = await getActivityStatistics()
```

### 直接查询数据库

```sql
-- 查询最近的100条审计日志
SELECT * FROM audit_logs 
ORDER BY created_at DESC 
LIMIT 100;

-- 查询特定组织的活动
SELECT * FROM audit_logs 
WHERE organization = 'TaobaoMSP' 
ORDER BY created_at DESC;

-- 查询特定类型的活动
SELECT * FROM audit_logs 
WHERE resource_type = 'prescription' 
ORDER BY created_at DESC;

-- 统计各类活动数量
SELECT resource_type, COUNT(*) as count 
FROM audit_logs 
WHERE status = 'success' 
GROUP BY resource_type;
```

## 注意事项

1. **性能考虑**：审计日志写入是异步的，不应影响主业务流程
2. **错误处理**：审计日志写入失败不应导致业务操作失败
3. **数据一致性**：确保区块链和MySQL中的数据一致
4. **隐私保护**：敏感信息应该脱敏处理
5. **日志清理**：定期清理过期的审计日志，避免数据库膨胀
