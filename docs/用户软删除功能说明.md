# 用户软删除功能说明

## 功能概述

管理员可以对系统用户进行软删除（停用）和恢复操作。软删除不会真正从数据库中删除用户数据，而是将用户状态标记为"已停用"，确保数据完整性和可追溯性。

## 核心特性

### 1. 软删除（逻辑删除）
- 将用户的 `status` 字段设置为 0（禁用状态）
- 用户数据保留在 MySQL 数据库中
- 区块链上的历史记录不受影响
- 已停用用户无法登录系统
- 可以随时恢复用户

### 2. 数据保护
- 用户相关的病历、订单、授权记录等数据全部保留
- 符合医疗行业数据合规要求
- 保持数据完整性和审计追踪能力

### 3. 双层架构
- **MySQL层**：逻辑删除（业务层面控制访问）
- **区块链层**：永久存证（合规层面保留历史）

## 使用说明

### 管理员操作

#### 停用用户
1. 进入"用户管理"页面
2. 找到需要停用的用户
3. 点击"停用"按钮
4. 确认操作
5. 用户状态变为"已停用"，无法登录

#### 恢复用户
1. 在"用户管理"页面，将状态筛选器改为"已停用"或"全部"
2. 找到需要恢复的用户（卡片显示为灰色，带"已停用"标签）
3. 点击"恢复"按钮
4. 确认操作
5. 用户恢复正常，可以登录使用

#### 筛选功能
- **正常用户**：只显示可以正常使用的用户（默认）
- **已停用**：只显示被停用的用户
- **全部**：显示所有用户（包括正常和已停用）

### 用户体验

#### 已停用用户特征
- 卡片显示为灰色半透明
- 右上角显示红色"已停用"标签
- 只能查看信息，不能编辑
- 显示"恢复"按钮代替"编辑"和"停用"按钮

#### 登录限制
- 已停用用户尝试登录时，系统提示："该账户已被停用，请联系管理员"
- 无法通过任何方式登录系统

## 技术实现

### 数据库层面

#### users 表 status 字段
```sql
status TINYINT DEFAULT 1 COMMENT '状态：1-正常，0-禁用'
```

#### 软删除操作
```sql
UPDATE users SET status = 0, updated_at = CURRENT_TIMESTAMP WHERE id = ?
```

#### 恢复操作
```sql
UPDATE users SET status = 1, updated_at = CURRENT_TIMESTAMP WHERE id = ?
```

#### 登录验证
```sql
SELECT * FROM users WHERE username = ? AND password = ? AND status = 1
```

### API 接口

#### 停用用户
- **接口**: `POST /api/v2/deleteUser`
- **参数**: `{ id: number }`
- **返回**: `{ code: 200, msg: "成功", data: { message: "用户已停用" } }`

#### 恢复用户
- **接口**: `POST /api/v2/restoreUser`
- **参数**: `{ id: number }`
- **返回**: `{ code: 200, msg: "成功", data: { message: "用户已恢复" } }`

### 前端实现

#### 状态筛选
```javascript
filterStatus: 1  // 1=正常, 0=已停用, -1=全部
```

#### 条件渲染
```vue
<template v-if="val.status === 1">
  <!-- 正常用户：查看、编辑、停用 -->
</template>
<template v-else>
  <!-- 已停用用户：查看、恢复 -->
</template>
```

## 安全机制

### 1. 管理员保护
- 不能停用最后一个管理员账户
- 系统自动检查管理员数量
- 确保系统始终有可用的管理员

### 2. 权限控制
- 只有管理员可以停用/恢复用户
- 普通用户无法访问用户管理功能

### 3. 审计日志
- 所有停用/恢复操作都会记录
- 包含操作人、操作时间、操作对象等信息

## 与区块链的关系

### 区块链数据
- 区块链上的用户注册记录永久保留
- 区块链上的交易历史不受影响
- 区块链数据作为历史存证

### MySQL 数据
- MySQL 的 status 字段控制业务逻辑
- 登录验证只检查 MySQL 数据库
- 前端显示基于 MySQL 状态

### 数据一致性
- 区块链：存储不可篡改的历史记录
- MySQL：控制当前业务状态
- 两者互补，确保数据完整性和业务灵活性

## 优势

1. **数据安全**：不会丢失任何用户数据
2. **可恢复性**：误操作可以轻松恢复
3. **合规性**：符合医疗行业数据保留要求
4. **审计追踪**：保留完整的操作历史
5. **灵活性**：可以根据需要随时启用/停用用户
6. **性能**：不影响系统性能，查询效率高

## 注意事项

1. 停用用户前请确认该用户不再需要访问系统
2. 已停用用户的历史数据（病历、订单等）仍然可见
3. 恢复用户后，用户可以立即登录使用
4. 建议定期审查已停用用户列表，确认是否需要恢复
5. 不要停用最后一个管理员账户
