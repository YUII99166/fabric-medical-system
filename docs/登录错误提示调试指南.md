# 登录错误提示调试指南

## 问题描述

用户反映登录注册时错误提示不显示，例如：
- 用户不存在时，不提示"用户名或密码错误"
- 而是显示"失败"或其他不明确的错误

## 错误流程分析

### 1. 后端返回错误

当用户不存在或密码错误时，后端返回：

```go
// LoginWithPassword 函数
if err.Error() == "用户名或密码错误" {
    appG.Response(http.StatusUnauthorized, "失败", "用户名或密码错误，请检查后重试")
}
```

HTTP 响应：
```
HTTP/1.1 401 Unauthorized
Content-Type: application/json

{
  "code": 401,
  "msg": "用户名或密码错误，请检查后重试",
  "data": null
}
```

### 2. 前端 axios 拦截器

由于 HTTP 状态码是 401（不是 200），axios 会触发 error 回调：

```javascript
service.interceptors.response.use(
  response => {
    // HTTP 200 才会进入这里
  },
  error => {
    // HTTP 401, 500 等会进入这里
    const res = error.response.data
    const errorMsg = res.msg  // 应该提取到 "用户名或密码错误，请检查后重试"
    return Promise.reject(new Error(errorMsg))
  }
)
```

### 3. Vuex store

```javascript
loginWithPassword({ commit }, userInfo) {
  return new Promise((resolve, reject) => {
    loginWithPassword(userInfo)
      .then(response => {
        // 成功处理
      })
      .catch(error => {
        reject(error)  // 直接传递错误
      })
  })
}
```

### 4. 登录页面

```javascript
this.$store.dispatch('account/loginWithPassword', userInfo)
  .then(() => {
    // 成功
  })
  .catch((error) => {
    const errorMsg = error.message  // 应该是 "用户名或密码错误，请检查后重试"
    this.$message.error(errorMsg)
  })
```

## 调试步骤

### 步骤 1：检查后端日志

启动后端服务，查看控制台输出：

```bash
cd fabric-mims-main/application/server
go run main.go
```

尝试用不存在的用户登录，应该看到：
```
登录失败: 用户名或密码错误
```

### 步骤 2：检查浏览器网络请求

1. 打开浏览器开发者工具（F12）
2. 切换到 Network（网络）标签
3. 尝试登录
4. 查看 `/loginWithPassword` 请求

**检查响应：**
- Status Code: 401 Unauthorized
- Response Body:
  ```json
  {
    "code": 401,
    "msg": "用户名或密码错误，请检查后重试",
    "data": null
  }
  ```

### 步骤 3：检查浏览器控制台

打开浏览器控制台（F12 -> Console），应该看到：

```
❌ 请求错误: Error: Request failed with status code 401
❌ 服务器错误响应: {code: 401, msg: "用户名或密码错误，请检查后重试", data: null}
❌ 提取错误消息 (msg): 用户名或密码错误，请检查后重试
登录错误: Error: 用户名或密码错误，请检查后重试
```

### 步骤 4：检查错误提示

页面上应该显示红色的错误提示框：
```
用户名或密码错误，请检查后重试
```

## 常见问题排查

### 问题 1：控制台没有任何输出

**原因：** 前端服务没有重启

**解决：**
```bash
cd fabric-mims-main/application/web
# 停止当前服务（Ctrl+C）
npm run serve
```

### 问题 2：控制台显示 "请求失败" 而不是具体错误

**原因：** request.js 的 error 回调没有正确提取 msg 字段

**检查：**
```javascript
// 在 request.js 的 error 回调中添加调试日志
error => {
  console.error('❌ 请求错误:', error)
  console.error('❌ error.response:', error.response)
  console.error('❌ error.response.data:', error.response.data)
  
  const res = error.response.data
  console.error('❌ res.msg:', res.msg)
}
```

### 问题 3：后端返回 "失败" 而不是具体错误

**原因：** 后端的错误消息设置不正确

**检查：** `fabric-mims-main/application/server/api/v2/account.go`

```go
// 确保这样写
appG.Response(http.StatusUnauthorized, "失败", "用户名或密码错误，请检查后重试")
//                                      ^^^^    ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
//                                      msg字段  data字段（实际的错误消息）
```

**注意：** 第二个参数是 `msg`，第三个参数是 `data`！

### 问题 4：前端显示 "失败" 而不是 data 中的消息

**原因：** request.js 优先提取 msg 字段，但后端把错误消息放在 data 字段

**当前后端实现：**
```go
appG.Response(http.StatusUnauthorized, "失败", "用户名或密码错误，请检查后重试")
//                                      ^^^^    ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
//                                      这是msg  这是data
```

**前端提取逻辑：**
```javascript
if (res && res.msg) {
  errorMsg = res.msg  // 会提取到 "失败"
}
```

**解决方案：** 修改后端，把错误消息放在 msg 字段：

```go
appG.Response(http.StatusUnauthorized, "用户名或密码错误，请检查后重试", nil)
//                                      ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^  ^^^
//                                      这是msg（错误消息）                 data为空
```

## 修复方案

### 方案 A：修改后端（推荐）

修改 `fabric-mims-main/application/server/api/v2/account.go`：

```go
// 修改前
appG.Response(http.StatusUnauthorized, "失败", "用户名或密码错误，请检查后重试")

// 修改后
appG.Response(http.StatusUnauthorized, "用户名或密码错误，请检查后重试", nil)
```

同样修改所有错误响应：

```go
// 参数解析错误
appG.Response(http.StatusBadRequest, fmt.Sprintf("参数解析错误: %s", err.Error()), nil)

// 用户名或密码为空
appG.Response(http.StatusBadRequest, "用户名或密码不能为空", nil)

// 用户名或密码错误
appG.Response(http.StatusUnauthorized, "用户名或密码错误，请检查后重试", nil)

// 其他错误
appG.Response(http.StatusInternalServerError, fmt.Sprintf("登录失败: %v", err), nil)
```

### 方案 B：修改前端（备选）

如果不想修改后端，可以修改前端的提取逻辑：

```javascript
// 在 request.js 的 error 回调中
let errorMsg = '请求失败'

// 优先使用 data 字段（如果是字符串）
if (res && res.data && typeof res.data === 'string') {
  errorMsg = res.data
} else if (res && res.msg) {
  errorMsg = res.msg
} else if (error.message) {
  errorMsg = error.message
}
```

## 推荐修复

采用方案 A，修改后端的所有错误响应，统一使用 msg 字段传递错误消息。

### 需要修改的文件

1. `fabric-mims-main/application/server/api/v2/account.go`
   - LoginWithPassword 函数
   - Register 函数
   - 其他所有返回错误的地方

2. `fabric-mims-main/application/server/api/v2/prescription.go`
   - 所有错误响应

3. `fabric-mims-main/application/server/api/v2/supplement.go`
   - 所有错误响应

### 统一的错误响应格式

```go
// ✅ 正确：错误消息放在 msg 字段
appG.Response(httpCode, "具体的错误消息", nil)

// ❌ 错误：错误消息放在 data 字段
appG.Response(httpCode, "失败", "具体的错误消息")
```

## 测试验证

### 测试用例 1：用户不存在

1. 输入不存在的用户名和任意密码
2. 点击登录
3. 应该显示：**"用户名或密码错误，请检查后重试"**

### 测试用例 2：密码错误

1. 输入存在的用户名和错误的密码
2. 点击登录
3. 应该显示：**"用户名或密码错误，请检查后重试"**

### 测试用例 3：用户名已存在

1. 尝试注册已存在的用户名
2. 点击注册
3. 应该显示：**"用户名已存在，请更换用户名"**

### 测试用例 4：网络错误

1. 停止后端服务
2. 尝试登录
3. 应该显示：**"网络连接失败，请检查网络后重试"**
