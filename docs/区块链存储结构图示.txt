  1. Go结构体定义

     │ type PrescriptionAccessLog struct {                                 │
     │     LogID                    string `json:"log_id"`                 │
     │     PrescriptionID           string `json:"prescription_id"`        │
     │     PatientID                string `json:"patient_id"`             │
     │     AccessorName             string `json:"accessor_name"`          │
     │     AccessType               string `json:"access_type"`            │
     │     AccessedAt               string `json:"accessed_at"`            │
     │     ...                                                              │
     │ }                                                                    │
     └────────────────────────────────────────────────────────────────────┘

  2. 序列化为JSON
     ┌────────────────────────────────────────────────────────────────────┐
     │ accessLog := &model.PrescriptionAccessLog{...}                      │
     │ accessLogBytes, err := json.Marshal(accessLog)                      │
     │ // 结果: JSON字符串的字节数组                                       │
     └────────────────────────────────────────────────────────────────────┘

  3. 创建复合主键
     ┌────────────────────────────────────────────────────────────────────┐
     │ key, err := stub.CreateCompositeKey("access-log-key", []string{    │
     │     logID,                                                           │
     │ })                                                                   │
     │ // 结果: "access-log-key\x00<logID>\x00"                            │
     └────────────────────────────────────────────────────────────────────┘

  4. 写入区块链
     ┌────────────────────────────────────────────────────────────────────┐
     │ if err := stub.PutState(key, accessLogBytes); err != nil {          │
     │     return shim.Error("写入失败")                                    │
     │ }                                                                    │
     │ // 数据永久存储在区块链中，不可篡改                                 │
     └────────────────────────────────────────────────────────────────────┘

  5. 获取交易ID
     ┌────────────────────────────────────────────────────────────────────┐

╔═══════════════════════════════════════════════════════════════════════════════════╗
║                            为什么使用JSON格式？                                    ║
╚═══════════════════════════════════════════════════════════════════════════════════╝

  优点 ✓                                    缺点 ✗
  ┌──────────────────────────────┐         ┌──────────────────────────────┐
  │ • 人类可读，便于调试          │         │ • 比二进制格式占用更多空间    │
  │ • 跨语言兼容（Go/JS/Python）  │         │ • 序列化有性能开销            │
  │ • 支持富查询（CouchDB）       │         │                               │
  │ • 灵活的数据结构              │         │                               │
  └──────────────────────────────┘         └──────────────────────────────┘

  格式对比:
  ┌──────────────┬────────┬────────┬──────────┬──────────┬──────────┐
  │ 格式         │ 大小   │ 速度   │ 可读性   │ 跨语言   │ 富查询   │
  ├──────────────┼────────┼────────┼──────────┼──────────┼──────────┤
  │ JSON         │ 大     │ 中     │ ✓        │ ✓        │ ✓        │
  │ Protobuf     │ 小     │ 快     │ ✗        │ ✓        │ ✗        │
  │ MessagePack  │ 中     │ 快     │ ✗        │ ✓        │ ✗        │
  │ 原始二进制   │ 最小   │ 最快   │ ✗        │ ✗        │ ✗        │
  └──────────────┴────────┴────────┴──────────┴──────────┴──────────┘


╔═══════════════════════════════════════════════════════════════════════════════════╗
║                            数据不可篡改性保证                                      ║
╚═══════════════════════════════════════════════════════════════════════════════════╝

  1. 哈希链
     Block 1 ──→ Block 2 ──→ Block 3 ──→ Block 4
       ↓           ↓           ↓           ↓
     Hash1       Hash2       Hash3       Hash4
               (含Hash1)   (含Hash2)   (含Hash3)

     如果修改Block 2的数据 → Hash2改变 → Block 3的前区块哈希不匹配 → 整条链失效

  2. 默克尔树
              Root Hash
             /         \
          Hash12      Hash34
          /    \      /    \
        Tx1   Tx2   Tx3   Tx4

     任何交易的修改都会导致根哈希改变

  3. 数字签名
     每个交易都有创建者的数字签名，证明交易来源，防止篡改

  4. 共识机制
     多个节点验证并达成一致，恶意节点无法单独篡改

  5. 分布式存储
     所有peer节点都有完整账本副本，单个节点损坏不影响数据完整性
