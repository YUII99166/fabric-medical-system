## 🎯 论文主要内容

### 系统概述

基于 Hyperledger Fabric 区块链技术的医疗信息管理系统（MIMS），实现了：

- 5种用户角色（管理员、医生、病人、药店、保险机构）
- 4个组织联盟链（协和医院、301医院、温江社区、监管中心）
- 7大功能模块（用户管理、病历管理、跨院授权、药品订单、保险报销、数据统计、健康档案）
- 双存储机制（区块链 + MySQL）

### 技术栈

**后端**：
- Go 1.18+
- Gin Web Framework
- Hyperledger Fabric 1.4.12
- MySQL 5.7+

**前端**：
- Vue.js 2.x
- Element UI
- ECharts
- Vuex + Vue Router

**部署**：
- Docker
- Ubuntu 20.04 LTS

### 创新点

1. **双存储机制**：区块链存储关键数据（不可篡改），MySQL缓存查询数据（提高性能）
2. **灵活参数支持**：智能合约支持6个或10个参数，根据角色动态传递
3. **跨院授权机制**：患者对医疗数据有完全控制权，医生跨院访问需授权
4. **完整医疗历史链**：支持补充诊疗记录，形成完整医疗历史
5. **数据可视化**：用户统计、联盟链架构、健康档案可视化

### 测试结果

- 功能测试：24个用例，100%通过
- 性能测试：支持100+并发用户，TPS 150
- 安全测试：6个用例，100%通过
- 兼容性测试：11个用例，100%通过

### 答辩准备

**可能的问题**：

1. 为什么选择 Hyperledger Fabric 而不是以太坊？
   - 联盟链适合医疗场景，性能更高，支持权限管理

2. 如何保证患者隐私？
   - 跨院访问需授权，数据加密存储，基于角色的权限控制

3. 区块链性能如何？
   - TPS 150，满足中小型医疗机构需求，可通过分片技术提升

4. 如何处理区块链和数据库数据不一致？
   - 先执行区块链交易，再同步数据库，区块链为准

5. 系统如何扩展到更多医疗机构？
   - 支持动态加入新组织，配置新的 Peer 节点即可
